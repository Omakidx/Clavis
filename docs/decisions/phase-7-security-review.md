# Phase 7 security review — findings and dispositions

**Date:** 2026-10-23 · **Scope:** the production PDF reader (`entrypoints/reader`, `components/reader`, `lib/pdf`), its use of the shared selection toolbar, Listen and explanation card, the PDF.js asset hook and CSP in `wxt.config.ts`, and the removal of the offscreen voice fallback (`lib/speech`, `lib/router`) · **Method:** independent read-only review with Playwright probes against a scratch build, using hostile PDFs built with pdf-lib (fake `gsk_TEST` keys, Groq intercepted, external hosts routed and aborted). An independent acceptance suite ([p7-reader-acceptance.md](p7-reader-acceptance.md)) added 32 more fixtures, including encrypted, CJK, wasm-decoded and hostile ones.

No script execution, HTML injection or network request from PDF content was found. Our code has no HTML sinks; PDF.js 6.4.299's rich text, popup and struct-tree paths are sanitised or text-only; asset URLs are fixed names under an extension-local base. Two Medium findings were fixed before commit.

| ID | Severity | Finding | Disposition |
| --- | --- | --- | --- |
| M1 | Medium (confirmed) | A double-click bypassed the link confirmation: a page-sized Link annotation opened the dialog on the first click and the second click landed on the centred "Open link". | **Fixed:** "Open link" ignores pointer clicks with `detail > 1` or within 500 ms of the dialog opening (keyboard works at once); links ignore `detail > 1`. Regression E2E with a full-page-link PDF. |
| M2 | Medium (confirmed) | `annotationMode: ENABLE` also renders RichMedia/Screen/Sound annotations, so one click decoded PDF-embedded audio/video inside the trusted reader (a media-decoder bug would expose the key and `scripting`). | **Fixed:** `lib/pdf/annotations.ts` filters each page's annotations to an allowlist (links, text/popup notes, FreeText, markup, stamps, widgets); media, file attachments, 3D and unknown types are dropped. CSP gained `media-src 'none'; frame-src 'none'; form-action 'none'; base-uri 'none'` as defence in depth (Chrome does not apply `media-src` to `blob:` media, so the allowlist is the control). Regression unit + E2E. |
| L1 | Low (confirmed) | 100,000 Link annotations on one page stalled every extension page for ~7 s (shared renderer). | **Fixed:** at most 1,000 annotations per page, with a banner when the cap applies. Regression E2E (20,000 links generated at test time). |
| L2 | Low (by design) | Invisible (render mode 3), tiny or image-covered text is in the text layer and can reach Explain as context (prompt-injection channel). | **Accepted and documented** (requirements §8 #4). Nonce delimiters and plain-text output limit the impact to a misleading explanation. |
| L3 | Low | The reader's message listener accepted any sender with the extension id, including content scripts (a compromised renderer could forge `TTS_EVENT`/`CLAVIS_OPEN_SELECTION`). | **Fixed:** only the background service worker (no tab, `/background.js`) is accepted. Unit test. |
| L4 | Low (hypothesis) | `mailto:` query parameters such as `attach=` were passed to the mail client. | **Fixed:** mailto keeps only the address, subject, body, cc and bcc; the dialog shows exactly what opens. |
| INFO-1 | Info | Offscreen leftovers: the contract keeps an always-unavailable `offscreen` engine slot; a stale comment; docs still described the fallback. | Comment and docs fixed; the contract slot is kept for stability (simplify later). |
| Design | High impact, low likelihood | The reader is a trusted context: a PDF.js DOM-XSS or renderer bug would reach storage (incl. the key), `scripting` in granted tabs, `tabs` and credentialed fetches. Its router allowlist is already minimal (public routes, `OPEN_SETTINGS`, disclosure acknowledgement). | **Later (backlog):** move PDF.js into a manifest `sandbox` page (opaque origin, no `chrome.*`), passing selections and link requests to `reader.html` by validated `postMessage`; estimated 3–5 days plus 2–3 days of E2E migration. Evaluate Trusted Types alongside. |

Verified sound: javascript:/file:/chrome:/chrome-extension:/data:/blob:/ftp:/tel: links are inert; Launch/GoToR/JS `app.launchURL` still go through the dialog; no scripting manager or download manager, so JS, SubmitForm, GoToE and FileAttachment actions do nothing; IDN hosts show as punycode and bidi characters are encoded; pages open with `noopener,noreferrer`; the 100 MiB and 5,000-page limits apply before parsing/rendering; only the selection, its page number (not in the prompt) and ≤ 1,000 characters of start-page context reach Groq; HIGH-1 protections (trusted events, closed root) are intact in the reader; no `web_accessible_resources`, so web pages cannot open or frame the reader; the built manifest matches `scripts/expected-permissions.json`.
